# 自定义 SlotMap 与 dod::slot_map64 性能对比

本次实测体现了明确取舍：自定义版本在遍历上更快，但 dod 的批量插入、随机空槽回填和内存占用更好。
查询和持续删插的结果随元素类型、规模而变化。自定义代码更短，并不意味着它能作为全面更快的替代品。

环境：Apple M1、16 GiB、macOS 27.2、Apple Clang 21，单线程 `-O3 -DNDEBUG -std=gnu++17`。
每种类型独立测试 1 万、10 万、100 万个元素，每组预热一次、计时七轮，取中位数。
没有绑定核心或锁定频率。具体环境及源文件 SHA256 位于 `results/2026-10-30/environment.txt`。

这里只测元素存储。使用项目里的实际类型及邻接 vector，但不构造合法网格、不执行拓扑维护。
详见 `README.md` 的方法与复现命令。所有校验通过；基准小规模 smoke 通过 ASan/UBSan，原有两项 CTest 通过。

## 百万级主要结果

每格是 **自定义 / dod**，单位 ns/项，越小越快。
插入、删除、复制按每元素计；遍历按每个存活元素计；删插按一对操作计。

| 操作 | Vertex | Dedge | Halfface | Cell |
|---|---:|---:|---:|---:|
| 从空容器批量插入 | 22.65 / 17.31 | 21.12 / 16.40 | 7.17 / 4.53 | 7.09 / 4.50 |
| 随机 get，全部有效 | 9.26 / 10.57 | 7.15 / 8.16 | 7.76 / 7.18 | 7.85 / 7.09 |
| 随机 contains 后 get，全部有效 | 9.20 / 11.74 | 7.13 / 9.58 | 7.69 / 8.84 | 7.83 / 8.76 |
| 随机 get，50% 失效 | 10.35 / 10.69 | 9.86 / 9.81 | 10.61 / 10.11 | 10.74 / 10.08 |
| 随机 contains，50% 失效 | 8.62 / 7.06 | 8.77 / 6.95 | 9.23 / 7.34 | 9.29 / 7.30 |
| 遍历 key 后 get，100% 存活 | 1.11 / 1.54 | 0.92 / 1.36 | 1.14 / 1.31 | 1.13 / 1.32 |
| 遍历 key 后 get，10% 存活 | 12.35 / 25.13 | 11.19 / 23.96 | 11.81 / 25.67 | 11.74 / 25.65 |
| 随机删除半数 | 85.63 / 101.99 | 91.02 / 101.47 | 13.94 / 15.89 | 13.91 / 15.66 |
| 回填刚删除的半数 | 98.34 / 56.32 | 96.60 / 57.65 | 97.96 / 25.93 | 97.70 / 25.73 |
| 随机删一个、插一个 | 197.30 / 235.41 | 281.12 / 207.57 | 49.84 / 43.32 | 49.71 / 43.24 |
| 复制无空洞容器 | 15.50 / 15.60 | 15.60 / 15.09 | 2.36 / 2.11 | 2.15 / 2.04 |

百万级密集遍历中，自定义耗时约为 dod 的 67%–87%；只剩一成存活时约为 46%–49%。
dod 的原生对象遍历也单独测试，结论与此处 key+get 的百万级遍历结果一致，完整数值见 SUMMARY.md。

随机空槽回填是自定义版本的明显短板：Halfface/Cell 的耗时约为 dod 的 3.8 倍。
以 Cell 为例，自定义七轮的中间 50% 区间为 97.60–97.96 ns/次，dod 为 25.71–25.79 ns/次，
远大于该测试点的轮间波动。持续删插则不能简单类推：Vertex 自定义较快，Dedge、Halfface、Cell 为 dod 较快。

密集复制的差距较小，特别是 Vertex 不能据此宣布谁更快。
**含删除槽位的复制双方均跳过**：原始 dod 已有已确认的对象生存期、空闲队列复制缺陷，
错误行为不能参与性能排名。本次没有修改 dod，也未对复制赋值、异常回滚计时。

## 扩容事件

已有 65536 个元素后，再插入一个。单位 µs/单次事件：

| 类型 | 自定义中位数 | dod 中位数 | 自定义最小–最大 | dod 最小–最大 |
|---|---:|---:|---:|---:|
| Vertex | 224.54 | 0.458 | 221.75–227.33 | 0.167–0.583 |
| Dedge | 196.50 | 2.750 | 195.79–198.88 | 0.250–3.041 |
| Halfface | 107.58 | 0.292 | 106.50–110.17 | 0.250–0.708 |
| Cell | 107.21 | 0.291 | 106.79–107.96 | 0.208–0.542 |

自定义在这个边界需要移动整个 vector 中的槽位，dod 只增加一页。
这是特定边界事件，不是总体插入的 p99，也不表示普通插入都需要上述时间。
dod 单次短事件受分配器状态和计时开销影响较明显，应同时看范围。
语义上，自定义扩容还会使先前取得的元素指针失效；它的 key 仍有效。

## 百万级堆空间

单位 MiB，计入容器及元素成员请求的空间，排除测试驱动 key 数组、分配器取整和运行库缓存；**不是 RSS**。
峰值来自独立分配统计进程，没有为计时进程添加统计开销。

| 类型 | 自定义密集占用 | dod 密集占用 | 自定义构建峰值 | dod 构建峰值 |
|---|---:|---:|---:|---:|
| Vertex | 117.41 | 107.01 | 124.00 | 107.01 |
| Dedge | 94.15 | 84.09 | 104.00 | 84.09 |
| Halfface | 72.00 | 61.26 | 108.00 | 61.26 |
| Cell | 72.00 | 61.26 | 108.00 | 61.26 |

本组规模下，自定义密集占用约高 10%–18%。差额与每槽布局、optional 状态/对齐、vector 的剩余容量有关。
增长时旧数组与新数组暂时共存，导致自定义峰值更高。四种实际元素均支持 noexcept 移动，
因此此处扩容使用的是移动，而非因为元素不能安全移动而退回深拷贝。

空间差距随容量边界变化：例如 10 万个 Cell，自定义为 9.00 MiB，dod 为 6.25 MiB；
不能把百万级的百分比直接推广到所有规模。两者删除元素后都保留相当部分存储供复用。

## 对设计的含义

- 当前自定义版本有明确的遍历优势，但需要正视空槽回填、扩容延迟和空间开销。
- 从实现推测，随机回填短板可能与空闲链表的 next_free 存在随机分散的槽位中有关：
  下一次插入的位置依赖上一次槽位读取，而 dod 从独立队列顺序取得空闲 key。
  这属于结合源码的解释，尚未通过硬件计数器或替换数据结构的对照实验单独证明。
- dod 将较紧凑的元数据与元素分开保存，可能有利于只查询有效性的场景；实际优势仍受工作集规模影响。
- 如果继续优化自定义版本，优先验证空闲索引的存储方式和容量预留；保留已验证的对象生存期及异常保护。
  是否替换 Mesh 的底层容器，应结合实际编辑轨迹中查询、遍历、删插的比例，不能只按一个微基准判断。
